UNITRADE — START HERE (BEGINNER FIREBASE SETUP)
================================================

Read this first. Do not delete your existing Firestore collections or documents.
Your screenshot already shows a Firestore database with chats, publicProfiles,
requests and users. That means you do NOT need to create another database.

PART A — EXTRACT AND CHECK THE WEBSITE
--------------------------------------
1. Download UniTrade-Complete-Fixed.zip and extract it to a folder.
2. Keep the supplied files together in one folder. Do not rename script.js,
   social.js, style.css, social.css, index.html or firebase-config.js.
3. Open firebase-config.js in a plain text editor (VS Code is recommended).
4. This package currently contains projectId: "example-fb860". This must match
   the Project ID shown in your Firebase Console. The display name can be
   different from the Project ID.
5. If the Project ID in your console is different, open Firebase Console >
   Project settings (gear) > General > Your project > Project ID. In the
   firebase-config.js file, replace the config object with the configuration
   from Project settings > General > Your apps > your Web app > SDK setup and
   configuration > Config. Copy the browser/Web app config, NOT a service
   account JSON file or Admin SDK private key.
6. Save firebase-config.js. Never put a service-account private key in a website.

PART B — ENABLE LOGIN
---------------------
1. Open https://console.firebase.google.com/ and select the correct project.
2. Left sidebar > Authentication. If prompted, click Get started.
3. Open Sign-in method (sometimes called Sign-in providers).
4. Enable Email/Password and click Save.
5. Enable Google, choose a support email, and click Save.
6. Open Authentication > Settings > Authorized domains.
7. Add the exact hostname where the website is deployed, for example:
   unitradeneo.vercel.app
   Enter only the hostname. Do not include https:// or a trailing slash.
8. If you test on a local web server, add localhost if it is not already listed.
   Do not open the site using a file:// URL.
9. Open Authentication > Templates > Email address verification. Check the
   verification email template. Later, test that the email arrives in Inbox or Spam.

PART C — PUBLISH THE FIRESTORE RULES (IMPORTANT)
------------------------------------------------
Your screenshot already shows Cloud Firestore > Database (default) > Data.
Follow these exact steps:
1. In the same database page, click the Rules tab near Data and Indexes.
2. Open the extracted file named firestore.rules in a text editor.
3. Select and copy the ENTIRE contents of firestore.rules.
4. In the Firebase Rules editor, select the existing rules and replace them
   with the copied contents.
5. Click Publish. Wait until Firebase confirms that the rules were published.
6. Do not use rules such as "allow read, write: if true". They expose data and
   allow anyone to change or delete it.
7. Do not delete chats, publicProfiles, requests or users. Publishing rules
   changes access permissions; it does not delete those records.

What the included rules do:
- A signed-in user can read/write their own private users/{uid} document.
- Phone and student registration/roll number stay in that private document.
- A limited public profile is stored separately in publicProfiles/{uid}.
- Student discovery and messaging require a verified email and a completed
  profile with phone, registration number and college information.
- Chats and chat messages are restricted to the chat participants.
- Collections not explicitly allowed by the rules are denied by default.

PART D — STORAGE RULES (ONLY IF YOU USE FIREBASE STORAGE)
---------------------------------------------------------
Profile saving does not require Firebase Storage. If your website uses Storage
for uploads, open Build > Storage > Rules and review storage.rules before
publishing. Do not change Storage settings if Storage is not enabled or used.

PART E — DEPLOY THE WEBSITE
---------------------------
1. Keep a backup of your currently deployed website.
2. Replace the corresponding deployed website files with all files from this ZIP.
3. If using Vercel, upload/push the updated project to the same Vercel project
   and wait for the deployment to finish. Keep index.html at the site root.
4. Open the deployed HTTPS URL, then hard-refresh:
   - Windows/Linux: Ctrl + Shift + R
   - Mac: Cmd + Shift + R
5. If the old site still appears, confirm the deployment finished and that the
   correct Vercel project/domain was updated.

PART F — TEST FROM A CLEAN ACCOUNT
----------------------------------
1. Open the deployed HTTPS website.
2. Create an account using Email/Password, or use Google sign-in.
3. If using Email/Password, open the verification email. Check Spam if needed.
4. Complete the campus profile. Required fields: name, phone, college, course,
   year and student registration/roll number. Department, hostel, city and bio
   are optional in the campus profile.
5. Click Save profile & continue. Profile saving is allowed before email
   verification; campus search and messaging require verification.
6. After verification, return to the website and refresh. Open Find students.
7. Test with two different accounts using the same canonical college. Search
   should show public profile fields only, never phone or registration number.
8. Test messaging only after both accounts have complete profiles and verified
   email addresses.

PART G — IF SAVE PROFILE STILL FAILS
------------------------------------
1. Open the deployed website in Chrome.
2. Right-click the page > Inspect > Console.
3. Try Save profile & continue again.
4. Read the error shown below the save button and any red Console error.
5. If the error says permission-denied, make sure you published firestore.rules
   to the same Firebase project named in firebase-config.js.
6. If it says Firebase did not initialise, check that firebase-config.js is in
   the same folder as index.html and that its project config is correct.
7. If it says auth/unauthorized-domain, add the website hostname under
   Authentication > Settings > Authorized domains.
8. If it says auth/operation-not-allowed, enable Email/Password and/or Google
   under Authentication > Sign-in method.
9. If the error mentions missing/insufficient permissions for publicProfiles,
   check that the private users/{uid} write succeeded first and that the new
   Firestore rules were published.
10. If you send a screenshot for help, hide email addresses, phone numbers,
    student registration numbers and other private information.

SECURITY / HONEST LIMITATIONS
-----------------------------
- The phone number and student registration number are required private fields.
  They are not used as public search fields.
- Do not use the browser to search or expose other students' private identifiers.
- Email verification proves access to an email address; it does not prove a
  person is enrolled at a college. True student verification requires an
  institution email policy, trusted directory, or administrator/backend review.
- The included rules are a starting point for this app's current data model.
  Test every feature before production use; security rules must match all actual
  Firestore writes and queries in the deployed application.
- Local JavaScript syntax checks cannot test your Firebase project, email
  delivery, hosting, or deployed rules. Those need to be tested in your project.
