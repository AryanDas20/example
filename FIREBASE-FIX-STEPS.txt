UNITRADE — PROFILE SAVE FIX AND FIREBASE SETUP
================================================

WHAT WAS FIXED IN THIS PACKAGE
- The profile save button is no longer silently disabled just because email verification is pending. It explains what is needed and checks the latest Firebase verification status when clicked.
- The save button shows “Saving profile…” while writing, prevents duplicate submits, and restores itself after success or failure.
- Firestore errors are logged in the browser console and shown with a more useful explanation (including permission-denied).
- Required fields: full name, phone number, college/campus, course, year of study, and student registration/roll number.
- Phone number is checked for 8–15 digits. Registration number must contain at least 2 characters.
- College full name and recognised acronym use one field. Matching is case-insensitive and common aliases (including IITG, NITS, GU and LPU) map to a shared campus key.
- Phone number and student registration number are written only to users/{uid}, not publicProfiles/{uid}.
- Firestore rules prevent creating/updating a public profile until the private user document has a phone and registration number.
- Profile completion is required before campus search and messaging.

IMPORTANT
The website code cannot fix a Firebase Console configuration that points to the wrong project, has no Firestore database, has an incorrect authorized domain, or has unpublished rules. Follow the steps below.

1. CONFIRM THE FIREBASE PROJECT
- Open https://console.firebase.google.com/ and select the Firebase project you intend UniTrade to use.
- In Project settings (gear icon) > General > Your apps, select the Web app.
- Copy its Firebase web configuration and compare projectId, authDomain, apiKey, appId and storageBucket with firebase-config.js in this package.
- If the current values do not match your intended project, replace the values in firebase-config.js with the values shown by your own Firebase Console, save, and redeploy the whole site.
- Do not paste a Firebase Admin SDK service-account private key into the website. The browser config is the Web app config.

2. ENABLE AUTHENTICATION PROVIDERS
- Firebase Console > Build > Authentication > Get started (if shown).
- Open Sign-in method / Sign-in providers.
- Enable Email/Password.
- Enable Google and choose a support email.
- Save changes.
- Phone/SMS authentication is not used by this package.

3. ADD YOUR DEPLOYED WEBSITE DOMAIN
- Authentication > Settings > Authorized domains.
- Add the exact host name for your deployed site, without https:// or a trailing slash (for example: your-project.vercel.app).
- Add localhost only if testing on a local web server.
- Do not test Firebase sign-in from a file:// URL. Run through localhost or HTTPS.

4. SET UP EMAIL VERIFICATION
- Authentication > Templates > Email address verification.
- Confirm the sender/template is enabled and the action link is valid for your site.
- Create a test account, check Inbox and Spam, click the verification link, then return to the website.
- In the profile modal, click “Check verification / send email link” if the page has not refreshed the status.
- Email verification confirms control of an email address; it does not prove college enrollment.

5. CREATE OR CHECK CLOUD FIRESTORE
- Build > Firestore Database.
- If there is no database, create one in the intended region.
- Open the Rules tab.
- Replace the current rules with the complete contents of firestore.rules from this ZIP, then click Publish.
- Do not replace the rules with allow read, write: if true. That would expose private data and permit abuse.
- The profile save works before email verification: it writes the private users/{uid} document first, then the limited publicProfiles/{uid} document. Email verification is required for campus messaging and marketplace actions. The public profile rule checks that the private phone and studentId fields exist.

6. CHECK STORAGE RULES IF USING UPLOADS
- Build > Storage > Rules.
- Review/deploy storage.rules only if Firebase Storage has been created and the website feature uses it. Profile saving itself does not require Storage.

7. TEST THE PROFILE SAVE
- Open the deployed HTTPS site and sign in.
- You may save the profile before verifying email; verify email before campus messaging.
- Fill all required fields. Phone number should contain 8–15 digits; include country code if appropriate. Enter your registration/roll number.
- Click Save profile & continue and wait for “Profile saved”.
- If it fails, open browser developer tools: Chrome/Edge > View > Developer > JavaScript Console (or right-click > Inspect > Console). Retry once and read the red error. This package also displays the Firebase error near the button.

COMMON ERRORS
- “Firebase did not initialise”: firebase-config.js does not load, config is incorrect, or Firebase SDK scripts failed to load. Check the Network tab and project config.
- auth/unauthorized-domain: add the exact deployed host in Authentication > Settings > Authorized domains.
- auth/operation-not-allowed: enable Email/Password and/or Google in Authentication > Sign-in method.
- permission-denied: publish the matching firestore.rules to the same Firebase project referenced by firebase-config.js. Confirm Firestore is enabled and the signed-in user is saving their own UID.
- Email not verified: click the link from the verification email, return to the website, then click the verification-status button.
- Profile saved but public profile fails: confirm the deployed rules are the rules in this ZIP and that the private users/{uid} write completed first.

8. DEPLOY THE WEBSITE
- Replace the deployed files with the files in this ZIP (keep the directory structure flat as supplied).
- Deploy/redeploy on your host (for example, Vercel) after saving firebase-config.js.
- Hard refresh the deployed page (Ctrl+Shift+R / Cmd+Shift+R) to avoid cached JavaScript.
- Test with two separate accounts. Confirm phone and registration number never appear in public student cards or publicProfiles documents.

SECURITY NOTES
- Phone number and registration number are private profile fields. Do not copy them into publicProfiles or listing documents.
- Searching by public name/course/college does not expose phone number or registration number.
- For production-grade student verification, use a trusted institution directory or an administrator/server-side verification flow. A free-text college name alone cannot prove enrollment.
- Syntax checks do not replace testing against your actual Firebase project. Live auth email delivery and Firestore rules must be tested in the Console.
