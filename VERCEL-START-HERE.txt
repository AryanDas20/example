UNITRADE — DEPLOY TO VERCEL FROM THE BEGINNING
==============================================

IMPORTANT: The ZIP must be extracted first. Vercel needs the actual website files,
not a ZIP uploaded as a single file. Keep index.html, script.js, social.js,
style.css, social.css, firebase-config.js and diagnostics.js together at the
project root.

A. BEFORE DEPLOYING
-------------------
1. Extract this ZIP into a folder.
2. Open firebase-config.js in VS Code or another text editor.
3. The included config currently points to projectId "example-fb860". In Firebase
   Console > Project settings > General, confirm the Project ID is exactly the
   same. If not, replace the whole config object with your Firebase Web app's
   config (Project settings > General > Your apps > Web app > Config).
4. Never paste a service-account JSON or Admin SDK private key into this file.
5. Save the file.

B. DEPLOY TO THE EXISTING VERCEL PROJECT (RECOMMENDED)
-----------------------------------------------------
Option 1 — If your Vercel project is connected to GitHub:
1. Open the extracted folder in VS Code.
2. Replace the old website files in the repository with these files.
3. Keep index.html at the repository root unless your Vercel Root Directory is
   intentionally set to a subfolder. The files must be in that configured root.
4. Commit and push the changes to the branch Vercel deploys (usually main).
5. Open Vercel Dashboard > your UniTrade project > Deployments.
6. Wait for the newest deployment to show Ready. Open that deployment URL.

Option 2 — If you are not using GitHub:
1. Open https://vercel.com/dashboard and select your UniTrade project.
2. Use the available project deployment/import workflow to upload or import the
   extracted project folder. If the dashboard does not offer direct folder upload,
   use the GitHub method above; Vercel does not treat a ZIP file as a live website.
3. In Project Settings > Build and Deployment, choose Framework Preset: Other.
4. For this plain HTML/CSS/JS site, leave Build Command empty (or use no build
   command) and set Output Directory to `.`. Root Directory must contain index.html.
5. Redeploy and wait until status is Ready.

C. FIREBASE SETTINGS THAT MUST MATCH
------------------------------------
1. Firebase Console > Authentication > Sign-in method: enable Email/Password and
   Google if you want both sign-in methods.
2. Authentication > Settings > Authorized domains: add the exact hostname shown
   in Vercel, such as unitradeneo.vercel.app. Do not include https:// or a slash.
3. Firestore Database > Rules: review and publish the supplied firestore.rules
   to the SAME Firebase project as firebase-config.js. Do not use public read/write
   rules. Keep a backup of existing rules before replacing them.
4. Do not delete existing Firestore collections.
5. Storage is not required for profile saving. Only publish storage.rules if you
   have enabled Firebase Storage and reviewed the rules.

D. AFTER DEPLOYMENT
-------------------
1. Open the new Vercel deployment URL (not an old preview URL).
2. Hard refresh: Mac Cmd+Shift+R; Windows Ctrl+Shift+R.
3. Click Sign in / Create account and test the forms.
4. Test the theme button and page navigation; these should work even before login.
5. Create/sign in to an account, complete the required campus profile, and save it.
6. Verify the email before using student search or messaging.
7. Test shared listings and requests using two accounts.

E. IF BUTTONS STILL DO NOTHING
------------------------------
1. Make sure the loader has disappeared. This package includes a fallback that
   hides it after a few seconds if initialization fails.
2. Right-click the deployed page > Inspect > Console.
3. Click the broken button again. Read the first red error, including the file and
   line number. Also check Network for failed requests to gstatic or Firebase.
4. This version displays a Firebase warning at the bottom of the page if Firebase
   failed to initialize, plus runtime JavaScript errors when possible.
5. Common causes:
   - Firebase SDK failed to load: check network/ad blocker and gstatic requests.
   - Firebase did not initialize: compare firebase-config.js projectId with Firebase.
   - auth/unauthorized-domain: add the exact Vercel hostname to Authorized domains.
   - auth/operation-not-allowed: enable the provider in Authentication.
   - permission-denied: publish the rules to the same project and check the failed
     collection/path in the error.
   - index.html is not at the Vercel output root: fix Root Directory / Output Directory.
6. If asking for help, share the error text or screenshot of Console. Hide emails,
   phone numbers, registration numbers, tokens, and other private data.

WHAT IS AND IS NOT CLOUD-BACKED
-------------------------------
Accounts, private profile documents, public campus profiles, chats, listings and
requests use Firebase integration. Several utilities (such as price estimation,
local Lost & Found matching, local interface preferences and some Vault metadata)
are browser-local features; a button cannot make these cross-device without adding
server-backed data models and matching Firestore rules. Storage-provider booking,
payment, and external social links are not live integrations in this static release.
